# 需求分析建模草稿

以下草稿用于在 draw.io 中重绘为正式提交图片。图中实体、处理和状态与当前 V2 系统实现一致，可直接作为课堂建模图的文字底稿。

## 数据流图 DFD

### 顶层

外部实体：学生、指导教师、实验室管理员、学院安全负责人、校园统一认证系统。

系统：ChemTrack 危化品全生命周期管理系统。

主要数据流：领用申请、审批结果、入库信息、库存查询、异常上报、预警通知、统计报表。

### 1 层处理

- P1 用户与角色管理
- P2 危化品档案与批次库存管理
- P3 采购、验收与入库管理
- P4 领用申请与分级审批管理
- P5 出库、使用与归还管理
- P6 库存、有效期与异常预警管理
- P7 废弃物处置管理
- P8 审计与统计报表管理

数据存储：D1 用户库、D2 危化品档案库、D3 批次库存库、D4 领用记录库、D5 审批记录库、D6 审计日志库。

## ER 图

核心实体：User、Role、Laboratory、Chemical、Batch、Location、Request、Approval、Usage、Disposal、Alert、AuditLog。

关键联系：

- User 1:N Request（申请人）
- Chemical 1:N Request / Usage / Alert / Disposal
- Request 1:N ApprovalRecord
- Request 1:1 UsageRecord
- UsageRecord 1:0..N Disposal
- Chemical 1:N Incident
- User 1:N AuditLog
- Procurement 1:0..1 Chemical（验收后形成批次档案）

## 状态转换图

危化品批次与领用单正常生命周期：

`待采购 -> 采购中 -> 待验收 -> 已入库 -> 可领用 -> 申请待审批 -> 教师已审批 -> 管理员已复核 -> 已发放 -> 使用中 -> 已归还 -> 待处置 -> 已处置`

异常状态：已过期、冻结、库存不足、审批驳回、归还数量不一致、泄漏上报、存储异常。

触发事件：到货、验收通过、管理员入库、教师审批、管理员复核、办理发放、实验开始、归还登记、处置完成、有效期到期、发现泄漏。

## 关键逆向约束

- 普通用户不能直接修改库存和历史审计记录。
- 高风险试剂不能跳过教师审批和管理员复核。
- 发放和归还均在事务中完成，库存不能小于 0。
- 实际使用量与归还量之和不能超过发放量。
- 过期批次不能作为正常领用对象。

## 演示数据说明

当前数据库中的试剂、库存和申请记录均为课堂演示数据，不代表真实实验室台账。
